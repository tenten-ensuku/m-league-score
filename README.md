# Mリーグ ドラフト成績

本番: https://m-league-score.netlify.app/

2026-27のドラフトチーム（てん・あじ・さとし、各10名）と個人成績を表示する静的アプリです。シーズン切り替えで2025-26も参照できます。

## 実行

```sh
npm ci
npm run check
node scrape.js
```

`dist/index.html` はファイルを直接開いて利用できます。Netlifyの公開対象は `dist/` です。

```sh
npm run test:browser
netlify deploy --dir=dist --no-build
```

ブラウザ検証はローカルのChromeを使います。CIではPlaywright Chromiumをインストールします。`TEST_URL` を指定すると、その公開URLに対して同じ検証を実行します。

## 集計ルール

- チームPT: 指名10選手のポイント合計。
- 通算: レギュラー、セミファイナル、ファイナルの個人PTをそのまま合算。公式チーム成績の持ち越し半減は適用しません。
- 収支: `2 * 自チームPT - 他2チームPT合計`。
- 前回比: 直前の記録日からの差。同日中の再取得では前日の記録を基準にし、増減を消しません。変更なしの取得では履歴を追加しません。
- 平均着順: 各ステージの1〜4着回数を合計して計算。出場なしは未確定表示。旧データの平均着順はレギュラーの記録として明示します。

## データの責任範囲

| ファイル | 用途 |
| --- | --- |
| `config/season.js` | 今期、選手名簿、ステージ、参照URL |
| `data/draft-2026-27.json` | 確定したドラフトrevision 30の保存。毎回の更新で再取得しない |
| `data/seasons/2026-27.json` | 正本。各ステージ成績、個人内訳、日別スナップショットを一括保存 |
| `data/seasons/2025-26.json` | 昨季40名・81件の履歴。既存の数値を維持し日付だけ年付きで並べ替え |
| `app-data.js` | 表示用の全シーズンデータ。自動生成 |
| `data.js`, `history.js` | 互換用出力。自動生成 |
| `archive/2025-26/` | 引き継ぎ時点の旧アプリと元データをそのまま保管 |

**生成ファイルを手編集しないでください。** JSONと生成済み履歴は破損・競合マーカーを検出したら処理を停止します。自動的に空配列で置き換える処理はありません。更新は検証済みの正本JSON一つをアトミックに置き換え、その後に画面用データを生成します。GitHubへのpushに競合があれば停止し、生成物の自動マージやforce pushはしません。

## 取得元とステージ移行

2026-09-15に実ページを確認しました。

- キンマwebの今期レギュラー: https://kinmaweb.jp/archives/279394 。従来の `/mleague-ranking/2026-regular` は404。記事見出しの `202-27` は掲載側の誤植なので、この記事に限り2026-27の画像メタデータを併せて確認します。
- 公式レギュラー: https://m-league.jp/stats/?season=L001_S025 。40名のポイント・試合数・平均着順をキンマwebと照合し、着順回数を取得します。不一致は更新を停止し、次回取得で再確認します。
- 公式ページの実際に有効なタブからセミ（`L001_S026`）・ファイナル（`L001_S027`）を検出します。未開始のコメントアウトされたURLは取得しません。
- セミ・ファイナルは公式のステージ別成績を使用します。今後キンマwebのURLが確定したら `config/season.js` の `kinmaUrl` へ追加することで照合も有効にできます。昨季のファイナル記事 `275195` は今期に使用しません。
- フェーズ別に保存するため、敗退選手の既得点は残ります。ページの年度・選択ステージ・名簿・欠損・試合数後退を検査します。固定記事番号を推測して進行を判断しません。
- キンマwebに終了日があるデータは終了日、公式だけで日付が示されない段階はJST取得日で記録し、画面にも「取得時点」と明示します。
- 前の段階が一度取得された後で消えた場合は、ゼロに戻さず停止します。公式の構造や識別子自体が変わった際は設定・パーサーの修正が必要です。

## 自動更新

`update.yml` の起動予定は火・水・金・土の02:07、02:37、03:07、03:37、06:07 JSTです（試合日の月・火・木・金の深夜から翌朝）。毎時ちょうどの混雑を避け、起動や掲載の遅延に備えて複数回確認します。GitHub Actionsは定刻実行を保証しておらず、数時間遅れる場合もあります。画面の更新日時は、取得の試行時刻ではなく最後に成績が変わった時刻です。

2026-09-16に起動遅延を確認しました。前日の02:00予定は05:43 JSTに起動し、当日の02:00予定は03:35 JST時点で未起動でした。取得・照合は正常で、手動実行で9月15日分を反映しました。[実行履歴](https://github.com/tenten-ensuku/m-league-score/actions/workflows/update.yml)で開始時刻と結果を確認できます。急ぎの場合は同画面の「Run workflow」または `gh workflow run update.yml --repo tenten-ensuku/m-league-score --ref main` で既存の検証・公開経路を起動します。

`npm ci` → テスト → 取得・照合・生成 → 正本と生成物をcommit/push → Netlifyへ一括deploy。スコアの変化がない定時実行ではdeployしません。手動実行は変化がなくてもdeployします。利用する既存Secretsは `NETLIFY_AUTH_TOKEN` と `NETLIFY_SITE_ID` です。

失敗した実行はGitHub Actions上で確認できます。取得失敗時に新しいゼロデータを本番へ公開することはありません。シーズン終了時は `schedule` を止め、翌季は新しいIDとドラフトを追加してください。

## 復旧

破損した場合はまず `git status` とGitHubの履歴を確認し、直前の正常な正本・生成ファイルを特定して復元します。`node scrape.js --init` は新規シーズン専用で、既存の正本がある場合は拒否します。`--dry-run` は取得・照合・移行を検証してファイルを書き換えません。

`npm test` は開幕日の固定HTML/JSONを使い、シーズンが進んでも同じ条件で破損防止と移行を検証します。ブラウザ検証は1440 / 768 / 390 / 360px、検索・絞り込み・CSV・モーダル・グラフの描画・昨季81件を確認します。
